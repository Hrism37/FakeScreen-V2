# 已知问题与兼容性说明

## 功能限制

1. **窗口级亮度不是所有机型都生效**
   `WindowManager.LayoutParams.screenBrightness` 由系统实现，部分 OEM 会忽略。此时模式 B 只剩黑色覆盖。可在设置中开启“系统级亮度备用”，但需要 `WRITE_SETTINGS`，并且会真正修改系统亮度（退出时恢复）。

2. **系统级亮度恢复存在极端竞态**
   如果应用在写入系统亮度后立刻被断电/强制杀掉，记录已落盘，但恢复要等下次启动。恢复前会核对“当前值是否仍等于应用写入的值”，若用户已改动则不覆盖。这保证了安全，但可能留下一个较低亮度，需要用户手动调回。

3. **无法保证进程/服务不被系统终止**
   MagicOS、MIUI 等系统可能清理前台服务。应用提供忽略电池优化与启动管理指引，但不使用任何“保活黑科技”，也不承诺永不掉线。

4. **“错误过多真正熄屏”与“Shizuku 真熄屏”模式依赖 Shizuku**
   没有 Shizuku 时无法在不申请设备管理员的前提下调用系统电源键。应用会明确提示，错误锁定仍生效；真熄屏模式会自动降级为纯黑覆盖，不会伪造熄屏成功。

5. **Shizuku 真熄屏实际使用的是系统电源键**
   Android 没有普通应用可用的“直接切断屏幕供电”公开 API。应用通过 shell 用户服务执行 `input keyevent 26`，效果等同于按电源键：屏幕真正熄灭，同时设备可能进入系统锁屏。应用不会绕过系统锁屏。

6. **音量键组合不需要 PIN**
   同时按音量加和减会直接开始/结束会话，这是用户要求的物理紧急出口。它比通知栏按钮更难误触，但仍然是“无需密码”的退出方式。设置中可关闭；关闭后应用外不能开始会话，覆盖层内也不能用组合键退出。

7. **音量键全局监听需要无障碍权限**
   应用外（后台）开始会话依赖 `VolumeKeyAccessibilityService`。该服务只请求音量键事件、声明不读取窗口内容，但仍属于敏感权限；不开启时只能在覆盖层获得焦点时用组合键退出。部分系统可能限制无障碍服务在后台启动前台服务，失败时会发通知说明。

8. **2.1.0 未真机验证**
   2.1.0 的黑屏优先、触摸显示 PIN、音量键快捷开关、Shizuku 真熄屏按用户要求停止真机测试，只完成了编译与单元测试。2.0.0 的安装/UI/Shizuku 授权验证结论不能直接套用到这些新行为。

9. **FLAG_SECURE 会阻止截屏**
   主界面开启了 `FLAG_SECURE`，防止 PIN 被截屏/录屏；用户无法直接截图应用界面。若需要截图做反馈，可临时用另一台设备拍摄。

10. **PIN 记录损坏时会被视为未设置**
   PIN 记录用 Android Keystore 密钥加密，清除锁屏密码、恢复出厂设置等操作可能使密钥失效。此时应用无法解密记录，只能要求重新设置 PIN。这是可用性与“永不丢失”之间的取舍。

11. **未做多用户/工作资料适配**
   应用按单用户设计，工作资料中会使用独立的应用数据。

12. **仅中文界面**
   代码与文档为中文；`values/strings.xml` 只有中文文案，没有完整英文翻译。

13. **Compose UI 测试未在设备上执行**
    只提供了测试骨架；本次交付没有真机/模拟器运行结果。

14. **平板分屏未专门适配**
    应用以全屏覆盖为目标；分屏状态下启动会话，覆盖层仍为全屏（系统行为可能不同）。

## 兼容性报告

应用内“设置 → 兼容性报告”会生成当前设备的：

- 厂商/品牌/型号/设备代号
- Android 版本、API、安全补丁、MagicOS 版本（可读取时）
- 分辨率、DPI、最小宽度
- 悬浮窗/通知/系统设置/电池优化状态
- Shizuku 状态、PIN 状态、当前会话
- 已知限制列表

报告只在本机生成，可复制到剪贴板，不会上传。

## 未验证声明

以下内容**没有**在真机上验证，不得作为已通过测试引用：

- 荣耀平板 GT Pro + MagicOS 11 上 2.1.0 的全部行为（2.0.0 仅完成安装、UI、Shizuku 授权验证）；
- 全屏覆盖能否完全遮住状态栏/导航栏；
- 窗口级与系统级亮度在具体机型上的实际效果；
- 后台服务在厂商省电策略下的存活时间；
- Shizuku 真熄屏模式与错误熄屏在 MagicOS 11 上的实际执行；
- 横竖屏旋转时的视觉连续性；
- 紧急呼叫、闹钟在覆盖层之上的表现（系统层面应始终优先，但未实测）。
