# 荣耀 MagicOS 11 适配说明

> **验证状态：2.0.0 部分验证（2026-11-13）；2.1.0/2.1.1 未真机验证（用户要求停止测试）。**
> 已在 HONOR ROD2-W69（荣耀平板，Android 17 / API 37，MagicOS_11.0.0.110）上完成安装、启动、首页/设置/PIN 界面、兼容性报告与 Shizuku 授权验证。悬浮窗授权需要手动操作系统设置页，因此全屏覆盖、亮度、通知紧急退出、旋转、异常恢复仍未在真机上执行。详见 [DEVICE_TEST_2026-11-13.md](DEVICE_TEST_2026-11-13.md)。

## 已实现的适配措施

| 系统行为 | 应用侧应对 |
| --- | --- |
| 悬浮窗权限管理 | 启动前检查 `Settings.canDrawOverlays`；未授权时跳转 `ACTION_MANAGE_OVERLAY_PERMISSION`；创建失败给出明确错误并清理会话 |
| 后台应用运行限制 | 使用前台服务（`specialUse`）+ 常驻通知；会话状态同步落盘；提供“忽略电池优化”入口和 MagicOS 启动管理指引；不使用无限循环、不滥用 WakeLock |
| 前台服务生命周期 | `START_STICKY`；服务被系统重启且 intent 为空时尝试恢复会话；超过配置时长或记录过期则恢复亮度并退出 |
| 应用切换后的悬浮窗 | 使用 `TYPE_APPLICATION_OVERLAY` 全屏窗口，不依赖 Activity；任务被划掉后服务继续运行 |
| 屏幕旋转 | 窗口 `MATCH_PARENT`，监听 `DisplayManager` 重新隐藏系统栏；Compose 按约束重排，横屏使用左右分栏、紧凑尺寸 |
| 状态栏/导航栏 | API 30+ 用 `WindowInsetsController.hide(systemBars)`，低版本用 `SYSTEM_UI_FLAG_IMMERSIVE_STICKY`；允许从边缘临时呼出，保证能下拉通知栏 |
| 亮度修改权限及效果 | 默认只用窗口级亮度（无需权限）；系统级备用必须显式授权 `WRITE_SETTINGS`；不写 0；退出恢复自动/手动模式 |
| Shizuku 可用性 | 通过 `Shizuku.pingBinder()` / `checkSelfPermission()` 实时检测；绑定死亡与授权变化会刷新状态；不可用时自动降级 |
| 系统进程管理 | 不做保活承诺；持久化会话记录 + 启动/开机检查；通知栏提供紧急退出 |
| 设备重启 | `BOOT_COMPLETED` 接收器在后台检查记录，按“未被用户改动且未过期”规则恢复亮度，不自动弹出界面 |

## MagicOS 需要用户手动确认的设置

不同 MagicOS 版本路径可能不同，应用内只给出文字指引，不调用未经验证的厂商 Activity：

1. **悬浮窗**：设置 → 应用 → 应用管理 → FakeScreen → 权限 → 悬浮窗（显示在其他应用上层）。
2. **通知**：设置 → 应用 → FakeScreen → 通知 → 允许通知。
3. **电池优化**：设置 → 电池 → 更多电池设置 → 电池优化 → FakeScreen → 不允许优化。
4. **应用启动管理**：设置 → 应用 → 应用启动管理 → FakeScreen → 关闭“自动管理”，手动允许自启动、关联启动、后台活动。
5. **锁屏清理**：部分 MagicOS 版本会在锁屏后清理后台，需要在“应用启动管理”里允许后台运行。

## 仍需在真机上验证的项目

| 项目 | 为什么需要真机 | 失败时的表现 / 预期降级 |
| --- | --- | --- |
| 悬浮窗能否覆盖状态栏/导航栏区域 | 厂商可能强制 inset | 顶部/底部露出系统栏，黑色区域仍覆盖主体 |
| 窗口级 `screenBrightness` 是否生效 | OEM 可忽略该字段 | 只黑屏不降亮度；可开启系统级备用 |
| 系统级亮度写入与恢复 | 厂商可能限制 `WRITE_SETTINGS` | 写入失败自动回退窗口级；退出时不写 |
| 自动亮度模式恢复 | 需要确认 `SCREEN_BRIGHTNESS_MODE` 行为 | 恢复后仍为自动模式 |
| 前台服务是否被清理 | MagicOS 后台策略强 | 服务被结束后亮屏可能残留低亮度；下次打开应用恢复 |
| 锁屏/解锁后覆盖层是否仍在 | 系统可能回收 overlay | 覆盖层消失，应用结束会话并恢复 |
| 通知栏能否下拉 | 全屏 overlay 可能影响手势 | 无法使用紧急结束，依赖电源键/计时器 |
| 屏幕旋转后的布局 | 平板横竖屏切换 | 重新隐藏系统栏，PIN 键盘自适应 |
| 多任务/分屏 | 平板特性 | 未适配分屏，覆盖层仍全屏 |
| Shizuku 在 MagicOS 11 的可用性 | 需无线调试启动 | 状态显示未就绪，核心功能不受影响 |

## 设计上的有意取舍

- **不伪装系统锁屏**：不显示运营商/时间/通知等锁屏元素，不申请设备管理员，不阻止电源键。
- **通知栏紧急结束不需要 PIN**：这是防止用户被永久锁在黑屏里的兜底。它意味着能下拉通知栏的人可以结束会话，属于明确披露的取舍。
- **不承诺进程永不被杀**：MagicOS 可能结束前台服务，应用只保证“下次启动时一致恢复”，不宣称常驻。
- **不自动拉起界面**：开机只做恢复检查，不弹 Activity，避免厂商判定为恶意自启动。

## 建议的真机验证顺序

1. 安装 APK，授予悬浮窗与通知权限。
2. 设置 PIN，先用模式 A 开始/退出，确认覆盖、状态栏、旋转。
3. 用模式 B 重复，记录进入前亮度与退出后亮度（`adb shell settings get system screen_brightness`）。
4. 开/关自动亮度，重复步骤 3。
5. 会话中撤销悬浮窗权限，确认自动结束与亮度恢复。
6. `adb shell am force-stop` 后重开，确认恢复提示。
7. 会话中重启设备，确认开机后的恢复行为。
8. 安装并授权 Shizuku，连续输错 10 次，确认真正熄屏。
9. 在应用启动管理中切换限制，观察服务存活时间。

将每一步的实际结果补充到 [TESTING.md](TESTING.md) 的表格中，未执行的项目不要标记为通过。
